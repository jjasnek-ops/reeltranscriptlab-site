Transcribe Instagram Video: Which Link Should You Paste?

To transcribe an Instagram video here, paste the complete HTTPS link of the public video itself. The page checks Reel, video-post, TV, and supported share-link paths, removes tracking text, and then sends the cleaned URL for transcription. A profile, Story, insecure URL, or link with credentials is rejected before a transcription request starts.

Start with the video's permalink

Open the individual Reel or video post in Instagram and copy its link. Do not start with a profile, a collection, a Story, or an embed URL. A link can look public in a browser and still be unavailable to a transcription provider, so this page checks the URL shape first and the media access second.

The accepted shapes below describe the current browser validator. They are a contract for what the input field will accept, not a promise that every public post can be retrieved.

What happens to the link before transcription

This section describes the current Reel Transcript Lab implementation so you can diagnose the exact handoff rather than guess what a generic Instagram transcript tool might do.

  1. Protocol and host are checked first. The browser requires https: and one of instagram.com, www.instagram.com, or m.instagram.com. Usernames, passwords, and non-default ports are rejected. This prevents a pasted address from silently pointing somewhere else.
  2. The path is checked against video forms. The validator accepts the five path families above. A profile path or a Story path produces the message Use a Reel, video post, or share link, not a profile or Story. Nothing is sent to the provider for that input.
  3. The URL is normalized. The page changes the host to www.instagram.com and removes the query string and fragment. Tracking text such as ?utm_source=... is not part of the URL sent onward.
  4. The server applies the same boundary. The Worker re-checks the secure Instagram host and the /reel/, /reels/, /p/, /tv/, and /share/ path pattern before calling the transcription provider. A browser that accepts a value does not bypass the server check.
  5. Only then does the provider receive the link. The request uses the cleaned URL with automatic transcript mode. The page may show a queued or processing state while the provider works; keep the tab open until the result or an error is shown.

The page's URL normalization and the server's second check are both repeatable from the public source. They explain why copying the exact video permalink is more useful than repeatedly pasting a profile or a shortened redirect.

What the request path can prove

  • The browser calls the same origin with the normalized URL; it does not send your Instagram password or ask for an Instagram login.
  • The server requires the page's request marker and same-origin request before it contacts the provider. A random cross-site caller cannot use the transcript route as a public proxy.
  • The first request asks for automatic transcript mode. If the provider returns a job identifier, the page polls that identifier and shows queued or active status instead of pretending the text is ready.
  • The browser gives a request two minutes to reach the API call, while a provider fetch on the Worker has its own 110-second abort window. A later provider timeout is therefore an observable failure state, not an empty transcript that the page silently invents.
  • When a completed response contains segments, the page joins their text for the visible transcript and keeps the segment start and end offsets for SRT and VTT downloads. A URL check never changes that output contract.

These details are useful when a link looks correct but the result does not appear: first decide whether the failure happened before the provider handoff, during retrieval, or after a queued job. That is a more reliable next step than changing a valid path to a different spelling.

A valid shape can still fail at retrieval

Passing the URL check only means the page can make a well-formed request. The provider can still return that the video was not found or is not publicly accessible, that it could not transcribe the video, or that capacity is temporarily unavailable. A public URL is not a guarantee that the media can be fetched.

Supadata's published Transcript Unavailable explanation says a video may have no captions or subtitles available. This page uses automatic transcript mode, but it cannot add speech that the provider cannot retrieve. If the link is valid, try the original Reel or video-post permalink once; if the same provider error remains, keep the exact message for support rather than changing the URL at random.

Five steps before you submit

  1. Open the specific public video, not the account page.
  2. Use Instagram's share control to copy the link.
  3. Check that the pasted text begins with https:// and uses an Instagram host.
  4. Submit once and keep the tab open while the status changes.
  5. If the provider fails, save the exact message and retry the canonical Reel or post link once.

Frequently asked questions

Can I use an Instagram profile URL?

No. A profile does not identify one video, so the browser rejects it before the provider is called. Open a specific Reel or video post and copy that permalink.

Are Instagram share links accepted?

The input validator accepts the three share-link path forms listed above. Provider retrieval is a separate step. If a share form fails after submission, use the canonical Reel or video-post link copied from the opened video.

Does a /p/ link always mean the post can be transcribed?

No. The path passes the link check, but a photo-only, removed, restricted, or speech-free post may still produce no transcript.

Why are tracking parameters removed?

The page strips the query string and fragment before sending the request. That keeps copied campaign text or a browser fragment from changing the media URL being checked.
